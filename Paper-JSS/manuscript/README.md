# StatsPAI JSS manuscript

This directory contains the English **Journal of Statistical Software
(JSS)** manuscript for StatsPAI. The manuscript uses the official JSS
class, reports Track A--C validation evidence, includes a deterministic
MCP trace for the agent-facing registry API, and describes the tagged 1.30.1 release
(PyPI wheel and git tag v1.30.1). The version/tag/changelog state of the
built tree is materialized in
`../replication/results/source_snapshot_manifest.{json,md}`, and the
release-boundary audit checks that the manuscript's versioned release
claim matches it.

For reviewer-facing commands and dependency tiers, start with
[`../README.md`](../README.md).

## How to compile

Preferred local rebuild:

```bash
cd Paper-JSS
make reproduce-jss
```

This runs the seven worked-example replication scripts plus the
deterministic agent trace, regenerates figures and all generated
supplemental tables, compiles `main.pdf`, and checks cited bibliography
keys. If Pandoc is installed, `make markdown` additionally refreshes
the local convenience `main.md` export; the PDF/LaTeX sources are
authoritative, and the Markdown export is not included in the JSS
submission archive.

Reviewer-facing validation audit:

```bash
cd Paper-JSS
make reproduce-jss-full PYTHON=../.venv/bin/python
```

`reproduce-jss` is the fast, self-contained manuscript rebuild. It is
the target expected to run on an ordinary reviewer machine without R or
Stata. It also writes the source-snapshot manifest so source-snapshot rows
are not undocumented release drift. `reproduce-jss-full` first runs that
target, writes the reviewer-facing Tier-1 transcript at
`replication/results/reproduce_tier1_output.txt`, and then regenerates
`replication/results/jss_full_audit.{json,md}`, which checks the
committed original-data parity, R/Stata parity rollups, coverage
artifacts, performance artifacts, schema quality, stability tiers, and
JSS validation API. It also regenerates
`replication/results/validation_evidence_audit.{json,md}`, which fails
if a certified/validated registry symbol lacks evidence notes or if a
certified symbol lacks attached R/Stata parity-module evidence. The
expensive primary reruns behind those artifacts remain separate because
they require optional software and more wall time.
For the licensed Stata leg, set `STATA_EXE=/path/to/stata-mp` before
running Tier 3; absence of Stata is reported as an optional-runtime skip,
not as live rerun evidence.

Final-release gate:

```bash
cd Paper-JSS
make release-audit PYTHON=../.venv/bin/python
```

This invokes `source_snapshot_manifest.py --strict-release`. It is
expected to pass only after the final clean release cut. The generated manifest includes a structured
checklist for the release cut: hand-edited worktree blockers, package tag
at `HEAD`, version consistency, finalized changelog, finalized package
source paths, and finalized Paper-JSS paths. Rows marked as source-snapshot
evidence remain source-tree evidence rather than already uploaded
PyPI-wheel evidence.

Submission archive:

```bash
cd Paper-JSS
make submission-ready PYTHON=../.venv/bin/python
```

This is the audited packaging path: it runs `reproduce-jss-full` and
then writes `build/statspai-jss-submission.zip` and a manifest, so the
zip contains the latest `jss_full_audit`, source-snapshot,
submission-risk ledger, reviewer evidence map, PDF render audit, JSS
house-style audit, and validation-claim lint and validation-evidence
manifests.
The archive intentionally excludes `.git/`, `htmlcov/`, `references/`,
LaTeX auxiliary files, the local Markdown exports, and inactive
long-form section drafts, while including the active manuscript
source/PDF, replication scripts/results, `src/statspai`, and the
parity/coverage test directories needed to audit the validation claims.
The script fails if the zip exceeds the 50 MB JSS attachment limit. Use
`make submission-package` only for a quick zip refresh after audit
artifacts are already current.

Container rebuild from the repository root:

```bash
cd /path/to/StatsPAI
docker build -f Paper-JSS/replication/Dockerfile -t statspai-jss .
docker run --rm statspai-jss
```

The container installs the local StatsPAI source tree from the build
context, rather than pulling StatsPAI from PyPI, because the paper
targets the local 1.30.1 tree. It also installs Poppler so the full
audit can render-check representative PDF pages.

Manual LaTeX-only rebuild:

```bash
cd Paper-JSS/manuscript
pdflatex -interaction=nonstopmode main.tex
bibtex main
pdflatex -interaction=nonstopmode main.tex
pdflatex -interaction=nonstopmode main.tex
```

Or, if you have `latexmk`:

```bash
latexmk -pdf main.tex
```

The current manuscript compiles with `pdflatex` from TeX Live 2024. The
substantive output is `main.pdf`; `main.md` is only a local convenience
export for quick reading and is excluded from the submission archive.

## Style status

- The submission-facing manuscript uses the official JSS class and bibliography style
  (`jss.cls`, `jss.bst`, `jsslogo.jpg`) with
  `\documentclass[article]{jss}` for the submission-facing manuscript.
  The `nojss` option is reserved for package-vignette derivatives and is
  rejected by `replication/scripts/verify_jss_style.py`.
- The previous article-class review source is preserved as
  `main-article-class.tex.bak`.
- Python code listings use a custom `lstlisting` style approximating
  JSS's `Sinput`/`Soutput`; JSS allows `lstlisting` for non-R languages.

## Citation discipline

All bib keys cited in `main.tex` and `sections/*.tex` are present in
`jss-bib.bib`; the verifier is run by
`Paper-JSS/replication/scripts/verify_citations.py`. The manuscript no
longer cites unpublished internal self-references.

Historical roadmap notes such as `../NEXT-STEPS.md` are local working
files and are excluded from the JSS submission archive.
