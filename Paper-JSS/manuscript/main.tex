%% Code listing style approximating JSS Sinput / Soutput.  We retain
%% listings (rather than jss.cls's fancyvrb CodeInput) for the numbered,
%% cross-referenceable captions the text relies on, but the rendering is
%% deliberately verbatim-equivalent:
%%
%%   columns=fullflexible + keepspaces  -- listings' default [c]fixed mode
%%     pads every glyph into a fixed box, which spreads identifiers into
%%     "sp . datasets . card_1995 ()" in the PDF and makes the code
%%     uncopyable.  fullflexible uses the typewriter font's natural
%%     widths, so a listing sets exactly as \verb would.
%%   upquote  -- straight ' and " so a reader can paste a listing into a
%%     Python prompt without silently getting curly quotes.
%%   no language=/keywordstyle=  -- JSS does not syntax-highlight code;
%%     bolding Python keywords was a house-style deviation.
%%
%% Every printed listing is executed verbatim by
%% replication/scripts/listings_execute_audit.py, so a listing that stops
%% being runnable fails `make verify` rather than reaching a reviewer.
\definecolor{codebg}{gray}{0.96}
\lstdefinestyle{Sinput}{
  basicstyle=\ttfamily\small,
  backgroundcolor=\color{codebg},
  frame=single, framesep=4pt, framerule=0pt,
  columns=fullflexible,
  keepspaces=true,
  upquote=true,
  breaklines=true,
  breakautoindent=false,
  breakindent=2em,
  postbreak={\mbox{$\hookrightarrow$\space}},
  showstringspaces=false,
  aboveskip=1.2\medskipamount,
  belowskip=0.6\medskipamount,
}
\lstdefinestyle{Soutput}{
  style=Sinput,
  backgroundcolor=\color{codebg!60!white},
}

\title{\statspai{}: Validation-Tiered \proglang{Python} Workflows for
       Causal Inference}
\Plaintitle{StatsPAI: Validation-Tiered Python Workflows for Causal Inference}
\Shorttitle{\statspai{}: Validation-Tiered \proglang{Python} Causal Inference}

\Abstract{
\statspai{} is a \proglang{Python} package for applied causal inference
and econometrics whose functions carry evidence labels. This article asks
what such a label certifies and describes a design that lets a user check.
The strongest check is the narrowest. For 40 entry points,
\code{sp.validation\_scope} reads a fitted object and reports which reference
runs covered its variant and inference option, and whether they compared the
standard error as well as the point estimate. More widely, a call trace bound
to the source files on its path establishes which implementation ran in each
of \RParityModuleCount{} modules compared with \proglang{R} implementations on
identical data (\RParityStrictCount{} at same-data parity, with
\proglang{Stata} references for \StataParityModuleCount{}). Those modules back
\ParityTrackACertifiedCount{} of the \RegistryCertified{} functions the registry
labels \code{certified}. The others rest on stored reference results, each
held by a test, with no finer record. Further tests hold the entry point a
label credits and whether each automated check applies to a fit. Stochastic
estimators are graded by seed-replicated equivalence against an explicit
margin. The evidence adds known-truth recovery, Monte Carlo coverage that
reports under-coverage where it occurs, and timings. Applying the design found
defects that numerical agreement alone had missed, among them parity rows that
compared \proglang{R} with itself and an instrumental-variables entry point
that returned CR1 errors when CR2 was requested. Seven worked examples,
executed as printed, and a licence-free replication path accompany the article.
The agent-facing interface is evaluated by mechanical and contractual checks,
not by agent behaviour.
}
