\section{Numerical parity and statistical validity}\label{sec:parity}

The empirical claim of this paper is narrower than the package surface.
\statspai{} registers \RegistryTotal{} public callables. Of these,
\RegistryCertified{} are \code{certified}, \RegistryValidated{}
\code{validated}, \RegistryApiStable{} \code{api\_stable}, and
\RegistryExperimental{} experimental. \code{certified} requires a
comparison with a named external reference, normally a same-data parity
row and for a stochastic estimator a seed-replicated equivalence test.
\code{validated} requires known-truth recovery or replication of published
numbers. This paper never adds the two up, since a combined figure would
let the second borrow the first's authority. Coverage runs and disclosed
disagreements are recorded against a function but earn no tier. A tier
also requires a stable API, which is why \ParityCrossLanguage{} symbols
have cross-language evidence but only \RegistryCertified{} are
\code{certified}: \ParityCrossNotCertifiedNames{} is still experimental.
A tier is earned by parity, so it can coexist with poor calibration.
\code{sp.dml} is \code{certified} on a linear-learner row although its
default learner under-covers (Section~\ref{sec:track-b}).

Of the \ParityCrossLanguage{} symbols with cross-language evidence,
\ParityTrackACrossCount{} rest on modules of the parity study or tested
aliases, and \ParityFrozenCrossCount{} on stored reference fixtures, each
held by its own test. The call trace and row-level register below cover
only the former. Of the \RegistryTotal{} callables, \ParityClassTotal{} are
classes, nearly all result or exception types that carry no grade, and
\ParityInfraTotal{} are infrastructure. Against the
\ParityEstimatorTotal{} estimator callables that remain, cross-language
coverage is \ParityEstimatorCrossLanguage{}
(\ParityEstimatorCrossLanguagePct{}), and \code{sp.parity\_summary()}
returns this split at call time.

A label is only as good as the chain that attaches it to the evidence
(Figure~\ref{fig:evidence-chain}). Each link has its own check, and each
check was written after the failure it guards against had occurred at
least once in this package.

\subsection{Estimands and what agreement does not establish}
\label{sec:statistical-contracts}

Numerical agreement does not establish identification. Two programs can
compute the same quantity, and both can be inappropriate for a design
that violates exogeneity, parallel trends, continuity, or overlap. The
suite's estimands are the standard ones: linear-projection coefficients
with a causal reading only under the relevant exogeneity or instrument
conditions, group-time effects
\(\operatorname{ATT}(g,t) = E[Y_t(1)-Y_t(0)\mid G=g]\) under no
anticipation, parallel trends with a stated comparison group, overlap, and
no interference, the cutoff effect under continuity, weighted untreated
counterfactuals for synthetic control, the PLR coefficient \(\theta\) in
\(Y=\theta D+g(X)+\varepsilon\), and AIPW averages of the forest's
\(\tau(x)\). Failure to reject a pre-trend test is not proof of parallel
trends, and placebo distributions for synthetic control are design-based
diagnostics, not sampling distributions.

\subsection{Numerical parity (Track A)}\label{sec:track-a}

The parity study runs each method three ways. Known DGP truths are used
whenever a truth exists. \statspai{} and the canonical \proglang{R}
implementation read the same \code{\%.16g} CSV file and write
full-precision JSON. Where a directly comparable \proglang{Stata} command
exists, it reads the same CSV. Four \proglang{R} references are transcriptions by the authors, not
packages (within demeaning, panel balancing, stacked DiD, and local-projection
DiD; modules 68, 69, 75, and 83 of Appendix~\ref{app:parity}). The study has \RParityModuleCount{} modules,
and \StataParityModuleCount{} carry a \proglang{Stata} reference. Each of
the \NoStataModuleCount{} without one records a measured, command-level
reason.
The same file need not give the same doubles. The \proglang{Python} side
parses each value with correct rounding, as \proglang{Stata} does.
\proglang{R}'s \code{read.csv} differs in the last bit on about 2\% of
values, a \(10^{-16}\) floor for \proglang{Python}--\proglang{R} agreement.
The package's test suite adds 13{,}214 reference-recovery tests, 469 tests
of published and replica values, and 32 slow coverage checks, as counted by
\code{sp.validation\_report(collect\_tests=True)}.

\paragraph{Which implementation ran.}
A parity row is evidence about a \statspai{} algorithm only if the
\proglang{Python} side ran one. A call-trace audit runs each module under a
profiler that records every call from \statspai{} into another package and
every subprocess it launches. The trace stores the SHA-256 of the module
script, of every \statspai{} source file that ran, and of the committed
result. A contract test fails if the registered classification and the
trace disagree, if one of those files has changed since the trace, or if
the trace meets a package outside the reviewed lists. Of the
\RParityModuleCount{} modules, \ParityNativeModuleCount{} run native code,
with \pkg{scikit-learn} appearing only as a user-chosen nuisance learner.
The other \ParityThirdPartyModuleCount{} wrap a third-party library (panel
fixed and random effects through \pkg{linearmodels}, ARIMA through
\pkg{statsmodels}) and are evidence about the wrapper's conventions. None
calls the reference it is compared against. Before 1.31 three did: the
Honest-DiD modules handed the computation to the \proglang{R} package, and
the RD headline used the official \pkg{rdrobust} \proglang{Python} port.
All three now run native code. The same trace found one more case in the
original-data results below, whose RD row agreed with \proglang{R} to
\(3.5\times10^{-16}\) because it was the authors' code compared with
itself; the native selector now agrees to \(3\times10^{-14}\). Five of the
six NHEFS modules there fit their propensity or outcome regressions with
\pkg{statsmodels}, and their rows are marked.

The native smoothness interval agrees to \(1.4\times10^{-8}\) with
\pkg{HonestDiD} once its simulated folded-normal quantile is replaced by
the exact one (the unmodified package sits \(3\times10^{-4}\) away on that
module's data). At \(M=0\) the native solver is within \(5\times10^{-16}\)
of the closed form. The native relative-magnitudes set, a port of
\citet{andrews2023inference}, accepts the same points of \pkg{HonestDiD}'s
finite \(\theta\) grid on sixteen cases. The native RD selector returns
\pkg{rdrobust}'s bandwidth and robust estimate to \TrackARdNativeGap{}.

\subsection{Evidence tiers and hard cases}\label{sec:validation-tiers}

\paragraph{Evidence is attached to configurations and outputs.}
A tier is attached to a function, but every artifact exercises one
configuration (a method variant, an inference option, a data condition,
a code path) and compares only some outputs. A parity row that pins the limited-information maximum likelihood (LIML) coefficient and its classical,
HC1, and CR1 standard errors says nothing about the HC3 standard error
of the same coefficient. For 40 entry points, among them the twelve suite estimators, the package
therefore records, per artifact, the value it actually ran on every
dimension that changes the computation (enumerated, never a wildcard).
It also records which outputs it compared: the point estimate, the
standard error, the coverage of the interval, or a diagnostic. A
dimension is ignored only for an output that provably does not depend
on it (the 2SLS point estimate does not depend on the covariance
estimator), and the reason is stored with the exemption.
\code{sp.validation\_scope(result)} reads the configuration of a fitted
object. For each output it reports the strongest matching evidence
(reference, seed equivalence, stochastic screen, coverage simulation,
disclosure, or none). Its overall status is \code{covered} when the
point estimate and its standard error both have a T1 or T2 row,
\code{estimate\_only} when only the point estimate does, and otherwise
\code{stochastic\_only}, \code{disclosure\_only}, or \code{not\_covered}. A dimension the fit did
not record is listed as unchecked and never matches. A queried value
outside a dimension's domain is refused.

The query has a limit that matters. It reads the configuration of a fit,
and no fit records its data. \code{sp.synth(method="classic")} on the
Basque replica therefore returns \code{covered}, on the strength of module
52, which ran the same configuration on a DGP with a unique solution. On
those Basque data the same call has no reference row
(Table~\ref{tab:basque-specs}). \code{covered} means ``this configuration
matched a reference on the data of that row''.

Building these records at this resolution found defects in the package and in
the records themselves. \code{sp.iv(..., vce="cr2", cluster=...)} silently
returned CR1 standard errors, because the option fell through a keyword
catch-all that the k-class fit ignored. It now reproduces
\code{sp.ivreg}'s covariance bit for bit, or raises for a method that
cannot compute it. The fixed-effects member \code{sp.fast.feols} was
pinned to \pkg{fixest} with \code{ssc="fixest"}. Its default, however,
charged absorbed effects that are nested in the cluster variable. A
coverage row run through that entry point (the previous row ran
\code{sp.panel}) found its CR1 errors 8\% above the Monte Carlo standard deviation
(SD), with
coverage 0.979. The default now follows \pkg{fixest} (coverage 0.955,
SE/SD 0.99).
The record's LIML row cited a module that runs \code{sp.liml}, which is a
separate code path from \code{sp.iv(method="liml")}. It now rests on a
test that runs the latter on the same data. \code{sp.sun\_abraham}'s
default aggregate, the equal-weighted average of post-treatment
event-time effects, had no reference row, since its parity module pins the
cohort-weighted aggregate. It now matches the same linear combination of
\pkg{fixest}'s coefficients to \(8\times10^{-12}\). An earlier pass found that \code{sp.iv}'s default classical covariance, printed
in Listing~\ref{lst:card-output}, was likewise unpinned. It is now held
to \pkg{AER}\code{::ivreg} on the original Card extract at
\(8\times10^{-11}\).

\paragraph{Causal forest: which Monte Carlo error?}
For a stochastic estimator two uncertainties must be kept apart. One is
sampling variation across datasets, which the reported standard error of
the ATE estimates. The other is the algorithm's own Monte Carlo
variation across seeds on \emph{fixed} data. ``Agreement within combined
Monte Carlo error'' is a statement about the second. It therefore cannot
be tested by dividing the gap between one \statspai{} fit and one
\pkg{grf} fit by their sampling standard errors, which is how this
package's own results once graded the row. The forest evidence therefore
separates three tasks. \emph{Truth recovery and inference} belong to
the coverage study (the AIPW row below). \emph{Estimand agreement} holds by
construction. Both engines report the doubly-robust AIPW average
\citep{athey2019generalized}, and given the same forest the AIPW
operator agrees with \pkg{grf}'s to machine precision.
\emph{Algorithmic agreement} is tested by refitting each engine under 50
seeds (20 at 8{,}000 trees) on fixed data, at 500, 2{,}000, and 8{,}000
trees, on two datasets.
The margin was chosen after inspecting the first dataset on an earlier
engine, so that dataset is development data. The second dataset, the
module-13 design, and the spaced-seed rerun of both came after the margin
was fixed. Seeds
are spaced \(10^5\) apart on both sides, because \pkg{grf} forests grown
from consecutive seeds share most of their random draws.
Table~\ref{tab:forest-seed-mc} reports the result. At every tree count
on both datasets, a two-one-sided test (TOST) establishes equivalence within
\(\delta = 0.1\) sampling standard errors, with an upper bound of at
most 0.049. A difference of that size moves a 95\% interval endpoint by
at most 2.5\% of its half-width. With Welch--Satterthwaite \(t\) critical
values in place of normal ones (20 seeds per side at 8{,}000 trees), the
bound rises by less than \(10^{-3}\). The engines' seed-to-seed
standard deviations are of the same order, but we do not claim they are
equal. Their ratio ranges from 0.79 to 1.48. Both fall with the number
of trees, from about 13--14\% of the sampling standard error at 500
trees to 6--7\% at the default 2{,}000. The claim is equivalence, not
identity. The engines are independent implementations, and at 8{,}000
trees, where Monte Carlo error is smallest, their seed means differ by
up to 0.019 sampling standard errors.

\paragraph{Synthetic control: one specification, two data sets.}\label{sec:scm-identification}
The classical-SCM row is a disclosed disagreement. The outer \(V\) optimization
is non-convex and donor weights need not be unique, and how much that
matters depends on the data (Table~\ref{tab:basque-specs}). Part of every
\proglang{Stata} gap here is the reference's own rounding. \code{synth}
rounds the donor weights to 0.001 before it builds the synthetic path it
reports. Rounded the same way, \statspai{}'s weights reproduce
\proglang{Stata}'s post-treatment gap to \(5\times10^{-16}\) on the
calibrated replica and to \(10^{-16}\) on the original
\code{Synth::basque} data. On both data sets the native solver and
\code{synth} therefore agree on every weight to the three decimals
\code{synth} reports. \proglang{R} \pkg{Synth} is \(1.8\times10^{-4}\)
away on the original data. On the replica it lands elsewhere, and
\proglang{R} \pkg{Synth} and \proglang{Stata} \code{synth} differ by
\(2.3\times10^{-2}\).
A single tolerance over both facts would hide the sensitivity a
practitioner needs to know about. A simulated design gives independent evidence
where an answer exists (row~4 of Table~\ref{tab:basque-specs}). When the treated unit is exactly a unique convex
combination of donors, the three implementations agree to
\(1.1\times10^{-9}\), the tolerance of the reference solvers, and the native
weights recover the true ones to \(2\times10^{-14}\).

\subsection{Monte Carlo coverage (Track B)}\label{sec:track-b}

The coverage study checks 95\% intervals on known DGPs, and it reports with
each rate the bias, the Monte Carlo SD, the mean reported standard error,
their ratio, and the interval length (Table~\ref{tab:track-b-b1000}). The artifact holds
thirteen \(B=1{,}000\) rows. Nine correspond to suite members, each run
through the member's own entry point or one asserted bit-identical to it.
The others are supplemental (2x2 DiD, entropy balancing, the interactive
DML model, and fixed effects through \code{sp.panel}). The RD density test,
classical SCM, and matching have no coverage row: the first is a diagnostic,
the second has no analytic interval, and matching's only inference row is a
\proglang{Stata} match for the non-default variance of
\citet{abadie2016matching}.

Ten of the thirteen rates lie in the binomial acceptance region
\([0.931,0.967]\) of the table caption, and in all ten the mean standard
error is within 4\% of the Monte Carlo SD. Three fall outside it: SDID
just below (0.928), the interactive DML model just above (0.968; ratio
1.04, mildly conservative), and DML PLR well below (0.883). Sharp RD
(0.934) is inside the region but at its lower edge, and it over-rejects
at the null (see below), so it is examined together with SDID. For \emph{sharp RD} and \emph{SDID} the
mean standard error is within 2\% of the Monte Carlo SD, so the
shortfall is not one of average scale. The tails of the studentized
statistic, the randomness of the standard error, and its dependence on
the estimate can still lower coverage, and the ratio alone does not say
which. For RD the question can be settled directly. On the first 200
draws, \proglang{R} \pkg{rdrobust}~4.0.0 returns the same intervals as
\statspai{} to better than \(10^{-10}\) and covers in exactly the same draws.
The shortfall therefore belongs to the procedure on this design, not to
the port. For SDID the placebo resampling is random, so the intervals
cannot be compared draw by draw, but their parts can. On all 1{,}000 draws
the point estimates equal those of \pkg{synthdid}~0.0.9 to
\(6\times10^{-14}\), and that package's own placebo interval covers 0.933.
The design has one treated unit and 20 controls, so the placebo standard
error is in effect a standard deviation over 20 refits, and both packages
multiply it by a normal quantile. With the exhaustive placebo standard
error, which takes each control once and has no simulation noise, the normal
quantile covers 0.932 and the \(t_{19}\) quantile 0.946. The shortfall
therefore lies in the critical value on a design with few controls, not in
the port.

\emph{DML PLR} clearly under-covers (0.883), and two things contribute.
Its bias is half a Monte Carlo SD, and its mean standard error is 12\%
below the Monte Carlo SD (ratio 0.88). \code{sp.dml} returns
\pkg{DoubleML}'s numbers to \(10^{-16}\) on the same folds and learners,
which rules out a porting difference. That does not make the interval
adequate, and the package says so where a user will see it.
\code{sp.validation\_scope} reports the default-learner PLR
configuration as \code{stochastic\_only}, with this row and its 0.883
attached, and \code{sp.dml}'s documentation states the limitation. We
varied one thing at a time on the same design
(\(B=500\)), and this locates the problem in the nuisance fit. With the
true nuisance functions, coverage is 0.952 and the bias vanishes. With a
random forest or a spline Lasso it is 0.940 and 0.938. With the default
gradient boosting it is 0.892 at \(n=500\) and 0.936 at \(n=2{,}000\),
where the bias is still 0.41 SD. DML's orthogonal score makes nuisance
error second order, but not zero. On this design the default learner's
regularization bias shrinks too slowly to be negligible at these sample
sizes.

The package offers an alternative a user can apply without choosing a
learner. On the same 500 draws, \code{sp.dml\_model\_averaging} with its
default roster (Lasso, Ridge, random forest, gradient boosting) and
short-stacking \citep{ahrens2025model} covers 0.948, with bias 0.07 of a
Monte Carlo SD and a standard-error ratio of 1.02.
One design cannot say whether the default learner is miscalibrated or was
unlucky, so Table~\ref{tab:dml-designs} repeats the comparison on six designs
that differ in what a nuisance learner has to get right. The default learner
under-covers on all six, from 0.890 down to 0.540, and its bias is always
toward zero, between half a Monte Carlo SD and almost two. It under-covers
even on step functions and interactions (0.816), the shape boosted trees fit
best. Short-stacking covers between 0.940 and 0.950 on five designs. On the
sixth, heteroskedastic interactions at \(n=2{,}000\), it covers 0.848 with a bias of
0.87 SD, because no learner in the default roster fits those interactions
well. Stacking is therefore the better default and not a guarantee. In 52\%
to 92\% of the draws the stacked estimate lies more than half a default
standard error from the default-learner one, so fitting both exposes the
problem, and we recommend reporting both. The default learner is not a safe
default, and we intend to replace it. Under the release rules of
Section~\ref{sec:parity-gaps} that change is announced a release ahead, so
release \StatsPAIVersion{} keeps gradient boosting, and a user of it should
pass learners explicitly or call \code{sp.dml\_model\_averaging}.

\subsection{Further checks}\label{sec:cross-estimator}\label{sec:high-n}

Estimators that should collapse to the same estimand on a given DGP are
held to each other, a loose screen for gross disagreement that can catch a
bug a single reference shares. Honest-DiD is pinned to the closed-form
breakdown value of \citet{rambachan2023more}. Event-study \emph{paths} need a
different test, because implementations differ in what each half of a path
is differenced against \citep{roth2026interpreting}.
\code{sp.event\_study\_convention()} records that choice per estimator.
Running it showed that \code{sp.did\_imputation} documented Stata's
\code{pretrends(k)} but shipped leads equal to the symmetric benchmark times
\(N_0/N\) \citep{li2025benchmarking}. The default now reproduces Stata's
leads and their standard errors to \(9\times10^{-13}\) and
\(5\times10^{-14}\).

\subsection{Adjudicating a disagreement}\label{sec:adjudication}

A set of parity results is only as credible as its procedure for the rows
that do \emph{not} agree, so every registered tolerance records its outcome. A disagreement on
identical data is assumed to be a \statspai{} defect until the first
diverging intermediate quantity (design matrix, weights, residuals,
sandwich meat) has been located. If the divergence is a documented
choice on both sides (a degrees-of-freedom divisor, a small-sample
cluster correction, an analytic versus influence-function variance),
the default follows the method's own authors. The alternative is exposed as a keyword,
and the gap is registered with its mechanism and bounded by the
tolerance. If the reference itself is the problem, or the solution is
not unique, the row is graded T4 and must carry independent evidence (a
second reference, an analytic identity, or a uniquely identified DGP). If exact agreement is impossible by
construction, as with forest randomization or the bootstrap, the row is
graded T3 only when both engines are refitted on fixed data under many
seeds and pass an equivalence test against a margin stated in
sampling-SE units. A single draw per side, a handful of seeds, or a
Monte Carlo tolerance is reported as a stochastic screen and earns no
grade. A gap that cannot be located is not called parity. It is graded
``unexplained'' in the tolerance audit and reported here as an open
item.
Contract tests enforce the procedure row by row, because a budget
justified by one row can silently cover another. Every joined row of a
T2 module that differs by more than \(10^{-6}\), estimate or standard
error, against either reference, must match an entry of a register that
states its mechanism (\RowGapEntryCount{} entries in
\RowGapModuleCount{} modules): a documented convention
(\RowGapConventionCount{}), the reference's numerics stopping short
(\RowGapNumericsCount{}), or a simulated quantity
(\RowGapStochasticCount{}, a stochastic screen). \RowGapPinnedCount{}
entries name rows that run \statspai{} under the reference's convention,
or a second reference, and join at \(10^{-6}\) or better. In release
\StatsPAIVersion{} every such row is registered. Three older Stata entries
predate it: two reconstructed from \statspai{}'s own quantities, the
group-average SE of \code{csdid} (fixed cohort shares,
\(6\times10^{-15}\)) and the PLIV factor \(N/(N-K)\) of
\code{ddml} \citep{ahrens2024ddml}, and a quantile tie-break
in the changes-in-changes command \code{cic} that touches one decile
(\(6\times10^{-3}\)) and the ATT integrating it (\(1.2\times10^{-3}\)).

Building the register found gaps that budgets had absorbed. The
Blinder--Oaxaca SE sat 1.2\% from \proglang{Stata}'s under a budget
written for \proglang{R}'s bootstrap; it is classical versus HC1 group
regressions and random versus fixed covariate means, and
\code{oaxaca, vce(robust) fixed} matches to \(2\times10^{-14}\). A
\(4\times10^{-4}\) pre-trends gap blamed on a randomized integrator was
mostly \pkg{pretrends}' fixed 1.96 cutoff, plus \code{uniroot}'s tolerance
(at most \(1.3\times10^{-7}\) with \code{threshold=1.96}). The frontier SEs sat \(1.3\times10^{-5}\) from
\proglang{R} and \proglang{Stata}, which agree with each other: round-off
in \statspai{}'s numerical Hessian, now fixed. The Sun--Abraham row was
carried as an open 0.7--2.2\% item across two releases instead of being
absorbed into a wider tolerance, and the bisection that closed it in
1.24.0 found a defect on the \statspai{} side
(Table~\ref{tab:correctness-history}). What remains is the cohort-share
term of the \citet{sun2021estimating} variance, which the default rows add as
\code{eventstudyinteract} does and which \code{share\_variance=False}
drops to reproduce \pkg{fixest} (both \(8\times10^{-12}\)).

\subsection{Auditing the attachment, not only the number}
\label{sec:attachment-audit}

A parity study checks that two implementations produce the same number. It
does not check that the function a reader calls is the function the study
ran. A package of this size exposes dispatchers, thin wrappers, and
convenience names said to reach the same core, and each inherits a grade it
did not earn on its own. An audit in release 1.26.0 found that, of eleven
registered alias attachments, seven cited a module that never called the
aliased name. Each surviving attachment now names a test that runs the alias
against the canonical entry point on the module's own data.
\code{sp.wooldridge\_did} was credited as an alias of \code{sp.etwfe} while
6.1\% away on that module's data. It was demoted, and it was re-certified
in 1.27.0 after a defect fix, once the ETWFE module called it directly. It reports
a different aggregation by default (15.9\% from \code{sp.etwfe}), so its
headline number is not the one that row pins. The configuration records found
two more cases: the LIML row cited a module that runs \code{sp.liml}, and
the 2SLS rows mixed tests of \code{sp.iv} and \code{sp.ivreg}. The same
failure reaches coverage rows. The causal-forest row ran through
\code{sp.causal\_question()}, which fitted the forest and then reported a
separate cross-fit estimator, so refitting with 30, 300, and 2{,}000 trees
gave identical results. It now reports the forest's own doubly-robust average
and was recomputed.

\subsection{Correctness history and residual risk}\label{sec:parity-gaps}

Appendix~\ref{app:corrections} lists the corrections that matter most, and
\code{CHANGELOG.md} and \code{MIGRATION.md} hold every entry. Two explain the
design. The 1.23.0 fix shows what a reference comparison catches and unit
tests miss: \code{sp.did(..., weights=)} never forwarded the weights to a
staggered branch, and only \code{did::att\_gt(weightsname=)} on identical
data exposed it. The 1.25.0 fix shows the limit of a parity study. The
causal-forest aggregation was wrong for a \emph{continuous} treatment, a
path that no parity or coverage row exercised, and the error surfaced in a
worked example.

The list is long, and its recent rows are not minor. A reader deciding
whether to rely on the package should read them as a statement about its
maturity. Nine of the ten minor releases from 1.31.0 to 1.40.0 changed an
output of a suite estimator in a configuration that no row had exercised,
among them a small-sample cluster covariance requested from \code{sp.iv},
clustered RD bandwidths and variances, tied matches, and a
Callaway--Sant'Anna covariate that varies over time. Pinned values also moved
in those releases, nearly always toward the reference. The largest were
standard-error conventions (quantile regression by 6.8\%, stacked DiD by 0.4\%). Solver
changes moved much less: three synthetic-control modules by at most
\(4\times10^{-7}\), and the Heckman two-step standard errors from
\(8.6\times10^{-5}\) to \(4\times10^{-9}\) of their references. Rows
with no reference to join also moved, some by more (the placebo SE of the unique-solution synthetic control by
15\%, a Honest-DiD breakdown value by 4\%, the Abadie--Imbens matching SE by
0.5\%). The evidence
in this article does not show that the unpinned configurations are now free
of such defects. It shows that the pinned ones are held to their references,
and that for the suite estimators the package can tell a user which kind a
given fit is. Freezing the release and archiving its artifacts make this
article checkable, but they do not reduce that risk.
\label{sec:convention-gaps}

Three rules bound what a release may change. The signatures of 32 everyday
estimation and post-estimation entry points are frozen by a test, and a break
needs a deprecation first. A change of default is announced at least one minor
release ahead by a \code{FutureWarning} that names the argument restoring the
old behaviour, as release \StatsPAIVersion{} does for two defaults. A
correction to a wrong number is not delayed, and each is flagged as a
correctness fix in \code{CHANGELOG.md} and \code{MIGRATION.md}. A user who
needs fixed numbers should pin the release, as this article does.
