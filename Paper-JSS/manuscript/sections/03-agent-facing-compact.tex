\section{The agent-facing registry API}\label{sec:agent}

\statspai{} exposes the surface a \proglang{Python} user calls to LLM
agents through typed schemas and an MCP server. The agent layer is a
software interface. Section~\ref{sec:agentbench} reports the mechanical
evidence for it and what that evidence does not show. No claim is made about
agent behaviour.

\subsection{Schemas and agent cards}\label{sec:why-schema}\label{sec:fn-schema}

A tool-using agent needs a typed object with parameter names, types,
defaults, required fields, and enumerated choices, not a prose help page.
\code{sp.function\_schema(name)} returns that object in the OpenAI tool
format. \code{sp.describe\_function(name)} and \code{sp.agent\_card(name)}
return planning metadata such as assumptions, preconditions, failure
modes, alternatives, and references. Generating a schema from a typed
signature is a solved problem. What is specific here is that the schema is
the statistical registry itself, so it carries the validation status of the
function and leads to the same evidence a human reader gets.

\subsection{Typed errors and the MCP server}\label{sec:exception-envelope}\label{sec:mcp}

Most estimator failures inherit from \code{StatsPAIError}, and
\code{to\_dict()} returns \code{kind}, \code{message},
\code{recovery\_hint}, \code{alternative\_functions}, and
\code{diagnostics}. Some failures still arrive as plain \proglang{Python}
exceptions. The MCP server adds \code{error\_kind} (such as
\code{assumption\_violation} or \code{numerical\_instability}) and a
\code{remediation} category (such as \code{weak\_instrument} or
\code{collinearity}), so an agent can branch without scraping English
messages. Listing~\ref{lst:typed-error} shows the record a misspelled
column produces.

\begin{lstlisting}[caption={A typed error, as a dictionary. An MCP client
receives this record with the additional \code{error\_kind} and
\code{remediation} fields.},label={lst:typed-error},captionpos=b]
>>> try:
...     sp.regress("lwage ~ educ + expr", data = card)
... except sp.exceptions.StatsPAIError as err:
...     record = err.to_dict()
>>> record["kind"], record["class"]
('column_not_found', 'ColumnNotFound')
>>> record["recovery_hint"][:39]
"'expr' not found; did you mean 'exper'?"
\end{lstlisting}

The \code{statspai-mcp} server exposes registered functions as MCP tools.
Tool inputs are generated from the registry schemas, outputs are JSON-safe
payloads plus \code{result\_id} handles, and failures use the record
above. By default \code{tools/list} serves a curated profile, because a
manifest with one tool per registered function is larger than an agent's
context holds. The profile lists hand-written estimator, workflow, and
pipeline tools and three meta-tools (\code{search\_functions},
\code{describe\_function}, \code{call\_function}), through which every
registered function stays reachable. \code{-{}-profile full} serves the
738 estimator-level tools; plots, datasets, and utilities stay out by
design. Chained tools for auditing, Honest-DiD sensitivity, generic
sensitivity analysis, Bacon decomposition, and citation accept result
handles, so an agent does not have to carry coefficient or covariance
arrays through its context.

\subsection{Questions, audits, and citations}\label{sec:causal-question}\label{sec:cite}\label{sec:agent-compare}

\code{sp.causal\_question(...)} accepts a requested estimand, treatment,
outcome, data, optional design, covariates, and instruments, and returns a
\code{CausalQuestion}. Its \code{.identify()} gives the plan and its
\code{.estimate()} an \code{EstimationResult} wrapping the fitted
estimator. \code{sp.audit(result)} produces a checklist of the design
evidence a reader will expect for a fitted result and points to follow-up
functions. Each check carries one of four statuses: passed, failed,
missing, or not applicable. The last is decided from the fit's own
metadata by an explicit rule. An over-identification test is not applicable
to a just-identified IV model, and the audit says why. The rules are not
complete. Generic fits can still be sent after checks that do not suit
them, so an audit is a prompt and not a verdict.

Every citation the package emits comes from a curated \code{paper.bib}.
Function specs store bibliography keys, result objects expose
\code{cite(format=...)}, and a missing key raises an error instead of
producing a plausible-looking reference. This addresses a known failure of
LLM agents, invented references. It checks that a key exists in the file.
It does not check the file, and the entries are verified by hand.
