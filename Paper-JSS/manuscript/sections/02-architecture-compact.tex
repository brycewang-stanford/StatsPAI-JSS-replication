\section{Software architecture}\label{sec:architecture}

\statspai{} is implemented in \proglang{Python} on top of
\pkg{NumPy} \citep{harris2020array}, \pkg{SciPy}
\citep{virtanen2020scipy}, \pkg{pandas} \citep{mckinney2010data},
\pkg{statsmodels} \citep{seabold2010statsmodels}, \pkg{scikit-learn}
\citep{pedregosa2011scikit}, and \pkg{linearmodels}
\citep{sheppard2025linearmodels}, with optional backends kept behind
extras and lazy imports. The architecture has four layers: registry,
dispatcher, result object, and output pipeline.

\subsection{Why an integration package?}\label{sec:design-principles}\label{sec:why-integration}

A reasonable alternative is to compose \pkg{statsmodels},
\pkg{linearmodels}, \pkg{DoubleML}, \pkg{EconML}, \pkg{DoWhy}, and
method-specific \proglang{R} or \proglang{Stata} bridges directly.
For a single specialized model that is often the right choice. The
friction appears when a project moves across identification designs,
because diagnostics, citations, validation status, error handling, export
formats, and agent schemas then stop sharing one contract. The package is
therefore organized by identification design, not by the historical
boundaries of \proglang{R} and \proglang{Stata} packages. Each design
reports its own diagnostics: balance and overlap, first-stage strength,
cohort support and event-study paths, bandwidth and density checks, donor
weights and placebos, and cross-fit diagnostics. What the designs share
is a post-estimation surface. They do not share identification
assumptions.

\subsection{Registry and discovery layer}\label{sec:registry}

The central data structure is a registry of \code{FunctionSpec}
records. Each entry carries a canonical function path, category, tags,
stability and validation status, parameter metadata, result class,
reference key, example call, and optional fields such as assumptions,
preconditions, failure modes, alternatives, and limitations. The registry
powers \code{sp.help()}, \code{sp.list\_functions()},
\code{sp.search\_functions()}, \code{sp.describe\_function()},
\code{sp.function\_schema()}, \code{sp.agent\_card()}, an import-free
\code{schemas/} bundle, and the MCP tool catalogue. One suite member,
\code{sp.fast.feols}, sits in the \code{sp.fast} namespace and is not
registered on its own.

The validation tier is not a paper-only artifact, but it does not arrive
unasked. A fit prints no tier and its summary carries none. A user or
agent obtains it by a separate call. \code{sp.help(name)} shows a
\code{Stability}/\code{Validation} header with the attached evidence
notes, \code{sp.describe\_function(name)} returns the same fields as a
dictionary (Listing~\ref{lst:validation-tier-output}), and
\code{sp.validation\_scope(fit)} reads the fitted configuration.

\subsection{Family dispatchers}\label{sec:dispatcher}

Family dispatchers reduce method sprawl without hiding assumptions.
\code{sp.synth} dispatches classical, synthetic difference-in-differences
(SDID), augmented, generalized, matrix-completion, penalized, and related
synthetic-control variants. \code{sp.decompose} covers Blinder--Oaxaca,
Gelbach, Fairlie, RIF, DFL, Machado--Mata, Melly, and related
decompositions. \code{sp.dml} dispatches partially-linear (PLR),
partially-linear IV, interactive (IRM), and local average treatment
effect (LATE) variants. Allowed \code{method=} values are enumerated in
the registry schema.

Inference uses one common keyword, \code{vce=}, but the menu differs by
entry point. \code{sp.regress} and \code{sp.ivreg} take classical,
heteroskedasticity-robust (HC1 to HC3), one- and two-way cluster-robust
(CR1), bias-reduced CR2/CR3 \citep{pustejovsky2018small}, the wild cluster
bootstrap \citep{cameron2008bootstrap,roodman2019fast}, and Conley spatial
errors \citep{conley1999estimation}. The fixed-effects entry points omit
HC2 and HC3, and \code{sp.panel} uses \code{vce=} only for its extended
menu (CR2/CR3, wild, jackknife, and Conley). An option a function does not
support raises an error. A matrix in continuous integration counts the
cells that are natively wired and pinned to a reference
(\code{reghdfe} \citealp{correia2017linear}, \code{boottest}, \code{acreg}
\citealp{colella2023acreg}, \code{ppmlhdfe} \citealp{correia2020fast},
\pkg{clubSandwich} \citealp{pustejovsky2026clubsandwich}, \pkg{sandwich}
\citealp{zeileis2020sandwich}), and that count may only go up. Not every
cell is pinned, and Section~\ref{sec:validation-tiers} shows how to ask.

\subsection{Result objects and output}\label{sec:results}\label{sec:output}\label{sec:workflow}

Most estimators return either \code{EconometricResults} or
\code{CausalResult}, which share summaries, plotting, dictionary and JSON
payloads, LaTeX and DOCX export, citations, audits, diagnostics, and
degradation records. This is why a mixed OLS/IV/DML table can be passed to
\code{sp.regtable} (or its \proglang{R}-style alias
\code{sp.modelsummary}), and why an MCP agent can keep only a result
handle. Not every class has joined this surface. \code{CausalForest} has
its own methods, renders as an empty column in \code{sp.regtable}, and
\code{sp.audit} treats it generically. Publication output renders mixed result classes as
LaTeX, Markdown, HTML, Word, Excel, or JSON. The layers combine into a
workflow with the same stages for human users and agents: detect
(\code{sp.detect\_design}, \code{sp.preflight}), fit (the dispatchers),
inspect (\code{summary()}, \code{sp.audit()}, sensitivity functions), and
report (\code{sp.regtable}, \code{cite()}, \code{sp.paper()}).

\subsection{Performance backbone}\label{sec:perfbackbone}

The performance-critical path is high-dimensional fixed-effect (HDFE)
absorption. Since 1.40.0 it runs in a compiled Rust kernel, published
separately as \pkg{statspai-hdfe}, which is a required dependency where a
wheel exists. Elsewhere the package falls back to \pkg{NumPy} and
\pkg{Numba} \citep{lam2015numba}. The two paths solve the projection to
the same tolerance but not bit for bit. Section~\ref{sec:compdetails}
reports which evidence ran on which path and how far apart they are.
