\section{Computational details}\label{sec:compdetails}

\statspai{} installs from PyPI (Section~\ref{sec:install}), and the article
describes release \StatsPAIVersion{} (tag \code{v\StatsPAIVersion{}}). Every artifact of
this article was regenerated in one environment, recorded in
\path{requirements-jss-lock.txt}: \proglang{Python} 3.10.20 with
\pkg{NumPy} 2.2.6, \pkg{SciPy} 1.15.3, \pkg{pandas} 2.3.3, \pkg{statsmodels}
0.14.6, \pkg{scikit-learn} 1.6.1, \pkg{linearmodels} 7.0, \pkg{Numba} 0.65.1,
\pkg{statspai-hdfe} 0.9.1, and \pkg{matplotlib} 3.10.9
\citep{hunter2007matplotlib}. \path{requirements-jss.txt} states the
supported version ranges. Optional heavy backends are lazily imported. No GPU
or commercial software is required.

The compiled kernel matters in two ways. The worked examples, listings, and
timings ran with it, as a user's default install does. The stored
\statspai{} side of the parity results ran without it
(\code{STATSPAI\_SKIP\_RUST=1}), so that those results do not depend on a
platform's wheel. We reran all \RParityModuleCount{} parity modules with the
kernel on. Estimates reproduce with a worst relative difference of
\(2.4\times10^{-10}\) (\code{25\_lmm}) and standard errors with
\(4\times10^{-9}\) (\code{27\_glmm\_aghq}, \(5\times10^{-10}\) in absolute
terms), both in iterative fits
(\path{replication/results/rust_on_parity_check.txt}). The
speed advantage in Table~\ref{tab:track-c-perf} for fixed effects is specific
to the kernel.

The \proglang{R} parity harness is pinned by
\path{tests/r_parity/renv.lock}, written by \pkg{renv}
\citep{ushey2026renv}. The reference environment uses
\proglang{R} 4.5.2. The packages behind the twelve-estimator suite are
\pkg{fixest} 0.14.0, \pkg{did} 2.5.1,
\pkg{Synth} 1.1-10, \pkg{synthdid} 0.0.9, \pkg{rdrobust} 4.0.0,
\pkg{rddensity} 2.6, \pkg{HonestDiD} 0.2.8, \pkg{DoubleML} 1.0.2,
\pkg{grf} 2.6.1, and \pkg{MatchIt} 4.7.2. The three-ecosystem worked
example adds \pkg{fect} 2.4.1 and \pkg{interflex} 1.4.0. The lockfile
and the per-row JSON provenance record exact versions for all
\RParityModuleCount{} modules, including \pkg{augsynth}, \pkg{gsynth},
\pkg{lme4} \citep{bates2015lme4}, \pkg{quantreg}
\citep{koenker2025quantreg}, \pkg{did2s} \citep{butts2022stage}, and
\pkg{rdmulti} \citep{cattaneo2020analysis}. Seven reference packages behind
stored fixtures sit outside that lockfile and are pinned in the fixtures:
\pkg{CBPS} 0.24 \citep{imai2014covariate}, \pkg{ebal} 0.2.1
\citep{hainmueller2012entropy}, \pkg{optmatch} 0.10.8
\citep{hansen2006optimal}, \pkg{Matching} 4.10.15
\citep{sekhon2011multivariate}, \pkg{sbw} 1.2 \citep{wang2020minimal},
\pkg{WeightIt} 1.7.0 \citep{greifer2026weightit}, and \pkg{ShiftShareSE} 1.1.0
\citep{kolesar2022shiftsharese}. The \proglang{Stata} comparisons use \proglang{Stata} 18 MP and record
official/community command versions in
\path{tests/stata_parity/STATA_ENVIRONMENT.md}. All \StataParityModuleCount{} \proglang{Stata}
modules and all \RParityModuleCount{} \proglang{R} modules reproduce their stored
JSON outputs within the \(10^{-9}\) floor. \proglang{Stata} requires a licence,
so the archive ships the stored results and matching do-files, and the paper
remains auditable from the \proglang{Python} and \proglang{R} results.

\subsection{Distribution and installation}\label{sec:install}

The package is distributed through PyPI
(\code{pip install statspai==\StatsPAIVersion{}}). On platforms with a
published wheel this also installs the compiled \pkg{statspai-hdfe}, and the
package falls back to \pkg{NumPy} and \pkg{Numba} elsewhere. Optional extras are
\code{dev}, \code{performance}, \code{bayes}, \code{deepiv},
\code{neural}, \code{fixest}, \code{rd-cct}, and \code{plotting}
bundles. The \code{rd-cct} extra installs the official \pkg{rdrobust}
\proglang{Python} port (\code{rdrobust>=2.0}, maintained by the
\pkg{rdrobust} authors), which backs the optional \code{bwselect="cct"}
path of Section~\ref{sec:ex-rd}. Because that port is GPL-3 licensed, it is an
opt-in extra, not a dependency of the MIT-licensed core, and no parity claim in
this paper depends on it. The reproduction lock includes it, version 2.0.0, for
the convergence check of Section~\ref{sec:ex-rd}. The test suite runs on Linux, macOS, and Windows in
continuous integration.

\subsection{Reproducibility of this paper}\label{sec:reproducibility}

The evidence is rebuilt by one standalone script,
\path{Paper-JSS/replication/reproduce.py}. The script distinguishes two
things a reader might mean by ``reproduced''. Its default licence-free
path, \code{-{}-tier 1}, takes a few minutes on the laptop of
Section~\ref{sec:performance}, well inside an hour. It
runs every generator the manuscript reads, then accounts for each of the
thirteen generated inputs of the compiled article, one by one, in
\path{replication/results/reproduce_manifest.json}.
Five are \emph{recomputed} from the installed package on that run: the
figures and tables of the worked examples, every printed listing and
transcript (replayed statement by statement and compared line for line),
the registry census behind every count in the text, and the MCP trace.
Eight are \emph{re-tabulated} from stored experiment results: the parity
tables, the coverage table, the forest seed and DML design tables, and the
timing table and figure. The frozen
experiments have their own entry points (Table~\ref{tab:reproduction}).
Each writes the artifact its table reads, so a recompute followed by
Tier~1 rebuilds the tables from fresh numbers. A group whose reference
side needs \proglang{R} fails when \proglang{R} is missing instead of
reusing the frozen reference, so fresh \proglang{Python} numbers are
never silently paired with old reference numbers. The timing comparator
likewise refuses rows whose two sides read different input bytes or
came from different runs. The \emph{\proglang{R} path} (\code{-{}-tier 2})
adds the pinned \code{renv} environment and re-executes every
\proglang{R} reference of the parity study on the stored data. (One module needs an archived release of its reference; the archive says which.) Auditing
the parity claim at full strength requires this path. The \emph{\proglang{Stata} path} (\code{-{}-tier 3}) re-executes the
\proglang{Stata} comparisons and requires a \proglang{Stata} licence.

Tier~1 was verified from a clean start. A fresh virtual environment was
built from the lock and the \code{v\StatsPAIVersion{}} source, in an unpacked
copy of the submission archive whose generated inputs had been deleted first
(\code{-{}-clean}), and it rebuilt all thirteen. Both sides of every parity row
can also be re-derived on their own.
\path{tests/r_parity/verify_reproduce.py} re-runs each \proglang{R} reference
on the stored data, and \path{tests/r_parity/verify_reproduce_py.py} does the
same for the \statspai{} side, regenerating each fixture CSV byte for byte. All
\RParityModuleCount{} modules clear a \(10^{-9}\) reproduction floor with no
exemptions.
